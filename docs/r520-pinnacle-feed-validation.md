# R520 Pinnacle 원배당 수신 수정 및 5줄 표시

## 공식 출처 확인 (2026-10-15)
- Pinnacle 직접 API: https://www.pinnacle.com/en/api — 개인/사업자 문의 및 이용 승인/조건 협의 경로. 새 계정·계약·유료 구독을 만들지 않았습니다.
- 기존 연결 The Odds API: https://the-odds-api.com/sports-odds-data/bookmaker-apis.html — Pinnacle(pinnacle) 포함. 제공사는 Pinnacle 공개 웹사이트 배당이어서 지연될 수 있다고 명시합니다.
- 응답 형식: https://the-odds-api.com/liveapi/guides/v4/ — 스포츠 전체 /odds 응답은 bookmaker.last_update를 제공하고, 단일 이벤트 /events/{id}/odds는 market.last_update를 제공합니다.
- 제공사 갱신 안내: https://the-odds-api.com/sports-odds-data/update-intervals.html — 주요 시장 경기 전60초/진행중40초 안내. 제공사 갱신 주기와 본 서버의 실제 조회 간격·잔여한도는 별개입니다.
- OddsPortal 변동배당 페이지도 조사했지만, 이 환경에서 실제 자동 수집 경로로 검증하지 못해 새 수집원으로 등록하지 않았습니다.

## 확인한 원인과 수정
- 기존 스포츠 /odds 수신에서 bookmaker.last_update를 버리고 존재하지 않을 수 있는 market.last_update만 검사하여 실제 배당이 INVALID_QUOTES가 되는 오류. 시장 시각이 없을 때만 업체 시각을 사용하고 원래 업체 시각도 보존합니다. 명시된 시장 시각이 오래되거나 비정상이면 신선한 업체 시각으로 덮어쓰지 않습니다.
- 기존8시간 freshness와30분 재조회 제한을5분 freshness/최소2분 간격으로 수정했습니다. 예산/잔여 reserve/기존 수집 window는 유지합니다. 5분마다 모든 경기를 반드시 수집한다는 뜻은 아닙니다.
- 리그 반복 조회가 뒤쪽 리그를 굶기지 않도록 미수집/가장 오래 미조회 리그를 우선합니다.
- 일시적 경기 매칭 색인이 없어도 이미 저장된 시장의 eventId를 재사용합니다. 리그·홈원정·시작시각을 원자료로 재검증하며 후보가 복수면 보류합니다.
- 실제 Pinnacle 원배당이 신선하게 있으면 데이터 분석에 가격·시각을 따로 표시합니다. 업체 중앙값과 Pinnacle 단일 가격을 혼동하지 않습니다.
- 국내·해외 표는 가격이 바뀌지 않은 연속 관측을 합쳐 최근 가격 변동 최대5행만 표시합니다. 데이터 분석도 최대5문단이며 보류 사유를 우선합니다. 원래 저장 이력은 삭제하지 않습니다.
- 기존 공개 수집 상태를 ?view=html로도 읽을 수 있게 해 실제 배포 후 확인이 가능하도록 했습니다. 비밀키를 노출하지 않으며 유료 요청을 추가하지 않습니다.

## 검증
- R520 공식 응답 형식 재현 테스트: 수정 전 실패, 수정 후 실제 Pinnacle 가격/시각의 캐시·이력 저장 통과.
- 시장별 오래된 시각 우선/미래 시각/미확인 시각 거절, 색인 유실 복구, 후보 모호성 보류, UI 유료 요청0회, 일일 한도 유지.
- 미수집 리그 우선순위, 5행 제한, 반복값 축약, 데이터 분석5문단, HTML 상태 비밀키 비노출 통과.
- 전체83개 중51개 통과/기존32개 실패, 신규 실패 없음. 실패 목록은 docs/r519-flow-integration-validation.md와 동일합니다. 네트워크 의존 replay-live.cjs, r370-compare-live.cjs 제외. 전체 성공으로 해석하지 않습니다.
- 원자료 수신 성공을 모의 검사만으로 운영 성공이라 주장하지 않습니다. 운영 확인은 별도로 해야 합니다.
